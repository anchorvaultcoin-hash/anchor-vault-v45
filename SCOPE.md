# AnchorVault V45 — SCOPE и известные решения (для аудиторов)

Документ фиксирует by-design поведение и принятые риски, чтобы аудиторы не
помечали их как баги. Все пункты — осознанные решения, не упущения.

## Доверенные допущения
- Поддерживаются только 18-decimals ERC-20, БЕЗ rebase. Rebase ломает учёт.
- `addSupportedToken` / `removeSupportedToken` — только creator. Поддерживаемые
  токены считаются добросовестными (не лгут balanceOf, без вредоносных хуков).
- Роли: `creator` (админ; выводит fee-пулы по 7-дневному таймлоку),
  `guardian` (только пауза). Конструктор запрещает creator == guardian;
  `transferCreatorship`/`transferGuardianship` запрещают слияние ролей.

## By-design (НЕ баги)
1. **Один активный сейф на токен на пользователя** (`activeVaultIdByToken`).
   Нельзя одновременно держать SAFE и FORTRESS одного токена. Намеренно — против распыления.
2. **Таймлок вывода считается от открытия сейфа** (`depositedAt`), не от последнего
   депозита. Довнесённые средства наследуют остаток таймлока.
3. **voluntaryLockUntil блокирует ВСЕ операции, кроме `panicWithdraw`.** При активной
   добровольной блокировке восстановление через recoveryAuthKey недоступно — только
   panic (штраф 20% на globalEmergency). Доводится до пользователя в UI.
4. **`panicWithdraw` без подписи** — страховка при потере обоих авторизационных ключей.
   Всегда шлёт на предустановленный `globalEmergency`. Безопасность panic полностью
   зависит от того, что globalEmergency задан верно (смена — 7-дневный таймлок + отмена).
5. **`block.timestamp`** используется для дедлайнов/таймлоков/кулдаунов. Интервалы —
   часы/дни, погрешность валидатора — секунды. Неэксплуатируемо (acknowledged).
6. **`maxWelcomeBonusClaims`** — creator-контролируемый параметр. При нехватке
   `rewardPool` бонус просто не платится; кап в коде не вводился ради гибкости.
7. **Компиляция требует `via_ir = true`** — штатный пайплайн Solidity.

## Принятые низкие риски
- **Грифинг входящих эскроу-переводов:** атакующий может занять
  `pendingIncomingTransfer[victim][token]`, блокируя легитимные входящие переводы
  того же токена на 48ч. Самозатратно (замораживает свой сейф). Risk: low.
- **Получатель может форсировать авто-отмену эскроу**, открыв свой сейф того же
  токена до подтверждения. Средства не теряются (возврат отправителю).
  Эмитится отдельное событие `SecureTransferAutoCancelled`. Risk: low.
- **Централизация:** creator может сменить guardian и де-факто контролировать паузу.
  Модель доверенного создателя. Пауза НЕ штрафует: обычный вывод 0.5% работает на паузе.
- **Теоретический overflow `nonce` (uint64):** недостижим (~5.8e11 лет при 1 оп/сек).

## Внесено по итогам ревью
- `initializeDistribution()` — проверка реального баланса контракта (защита инварианта).
- `_accrueFees`: `rewardsAmt = penalty > sum ? penalty - sum : 0` (defensive, underflow недостижим).
- `rescueERC20(token, to, amount)` — изъятие СЛУЧАЙНО присланных НЕподдерживаемых
  токенов. Только creator. Поддерживаемые токены спасать запрещено (инвариант).
- `SecureTransferAutoCancelled` — отдельное событие для race-отмены эскроу.
- Лицензия: BUSL-1.1 (контракты проекта); OpenZeppelin — MIT.

## Главный инвариант (проверяется фаззингом)
balance(ANCR) >= lockedPrincipal + creatorFees + strategicReserve + rewardPool.
Тест `invariant_Solvency` — 256 прогонов, не нарушается.

## Статус проверок
- Foundry: 16/16 (unit + EIP-712 + distribution + rescue + invariant).
- ganache: 24 функц. + 43 атакующих + 9 distribution + 4 rescue — все зелёные.
- Slither 0.11.5: 0 реальных уязвимостей (остальное — OZ / by-design / косметика).
- Компиляция: solc 0.8.26, via_ir, 0/0, ~22.8 КБ.
